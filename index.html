Order Cutoff → Handover Cutoff Padding
Every hub × partner combination carries two deadlines: an Order Cutoff — after which new orders roll to the next day's wave instead of this one — and the Handover Cutoff that CPT is measured against. The gap between the two is that hub's padding: its real processing runway. Thin padding is a leading indicator of CPT breach, independent of volume or backlog, and both the weighted-average and the raw hub-level view need to come down together.

Architecture Notes — for Product & Data Engineering
What this screen assumes exists underneath it, and what changes versus the current Metabase build.
WHAT'S WRONG WITH THE CURRENT BUILD
  • 01Cutoffs are hardcoded in SQL, not config. The live Metabase query encodes ~25 distinct hub_id/carrier cutoff rules as a CASE-statement stack.
  • 02The query is duplicated per warehouse. ps.warehouse_id = 2 is hardcoded even in the "network" script.
  • 03Carrier + cutoff time is baked into a display string — e.g. "08)Blue-dart-162-2:55PM" — with no clean dimension model behind it.
  • 04Only one breach signal exists — Handover-vs-cutoff. There is no early-warning tier, and no physical pickup confirmation.
  • 05RCA lives in email, not in the data model — 15+ recipients, free text, inconsistent labels per site.
  • 06No leg-by-leg, wave-by-wave visibility — the current summary shows terminal buckets, not "5 stuck in Verified against the 3PM cutoff."
PROPOSED DATA MODEL
Shipment_Master
  • shipment_id / order_id / master_shipment_id
  • site_id, fulfillment_type, is_express, carrier_id
  • sku, title, units, current_container
  • current_leg, cutoff_wave_id, pickup_confirmed
  • status (clear/wip/breach/stuck)
Leg_Event_Log
  • event_id, shipment_id, leg
  • scan_timestamp, operator_id, station_id
  • picklist_id / crate_id
Cutoff_Master (config)
  • site_id, carrier_id, is_express
  • cutoff_time, effective_from/to, status
  • drives every grid column header
Pickup_Confirmation_Log
  • shipment_id, carrier_id
  • dispatched_at, pickup_confirmed_at
  • powers the Partner Pickup table
RCA_Log
  • shipment_id, bucket, sub_reason (enum)
  • captured_by/at, site_id
Site_Directory / Carrier_Directory
  • site_id, site_code, site_name, type
  • carrier_id, carrier_name, active
GRID CELL COMPUTATION — PSEUDOCODE
for each site: waves = Cutoff_Master rows where site_id = site -- becomes the grid's columns for each leg in [Verified, Processing Pendency, Picking, Packed, Prepared, Dispatched, Handover]: for each wave in waves: cell = shipments where site=site and current_leg=leg and cutoff_wave=wave if leg == Handover: cell.status = CLEAR elif now() > wave.cutoff_time: cell.status = BREACH -- today's only signal else: cell.status = WIP Partner_Pickup table (same site, same wave set): for each carrier: assigned = shipments where carrier=carrier and current_leg in [Dispatched, Handover] confirmed = assigned where pickup_confirmed = true status = BREACH if now() > wave.cutoff_time and pending>0 else PENDING if pending>0 else ON-TIME
